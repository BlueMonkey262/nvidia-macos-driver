# H.264 video on pre-Blackwell GPUs

## How it is built (read this first)

The video codecs are **prebuilt binaries** that ship in the package (`libnvdec_h264.dylib`, `libnvenc_h264.dylib`, ...).
There is no source for them in this repository. They were written for Blackwell (RTX 50) and tile frames in the
Blackwell layout; earlier NVDEC/NVENC engines use the classic layout (issue #65 upstream).

- **Decode:** `tools/make_nvdec_t2d.py` changes one byte of the decoder (upstream's tool; the package ships the result as
  `libnvdec_h264_t2d.dylib`).
- **Encode (this fork):** `tools/make_nvenc_t2d.py` patches the Blackwell encoder binary: it redirects the two inline
  tiling loops to replacement loops that write the classic (t2d, block height 2) layout. The plugin
  (`plugin/NVMTLDevice.m`, `nvmtl_nvenc_h264_allowed`) registers the result as a VideoToolbox encoder on Turing only.
  So this is a **binary patch, not a native encoder**: everything past the tiling (engine setup, rate control,
  bitstream) is upstream's closed library, written for Blackwell and untouched here.

The patched library is not committed. Build it from the 2.2.0 package's encoder:

```bash
python3 tools/make_nvenc_t2d.py libnvenc_h264.dylib libnvenc_h264_t2d.dylib   # refuses any other input library
codesign -f -s - libnvenc_h264_t2d.dylib
# copy next to NVMTLDriver in /Library/GPUBundles/NVMTLDriver.bundle/Contents/MacOS/, build the plugin, restart apps
```

Set `NVMTL_NO_NVENC=1` in a process to keep it on Apple's encoder.

**Low-latency specification.** ffmpeg's `h264_videotoolbox` (so Sunshine) asks for `EnableLowLatencyRateControl`
whenever it is in low-delay mode. VideoToolbox refuses that on a GPU that is not Apple's (its log says
`VCPRateControlSession: Hardware support is not available`) and the session fails with -12902, so Sunshine falls back to
software x264. Our encoder is constant-QP and does not use that rate-control layer, so in any process where it is
registered the plugin (`plugin/nvmtl_vt_spec_hook.h`) removes that key from H.264 specifications before the call reaches
VideoToolbox (it rebinds `VTCompressionSessionCreate` and `VTCopySupportedPropertyDictionaryForEncoder` in every loaded
image). The same hook fixes a second problem: ffmpeg opens a session and then calls `VTCopySupportedPropertyDictionaryForEncoder`
with it still open; VideoToolbox answers that by instantiating the encoder, the library allows one engine per process
(see Known limits) and the lookup fails with -12908, which ffmpeg treats as fatal. The plugin fetches the (static)
dictionary once before the first hardware H.264 session and serves it from the cache when a later lookup fails that way.
It applies to every app, not only Sunshine. `NVMTL_NO_VT_SPEC_HOOK=1` turns it off. An app that calls VideoToolbox
before it touches Metal still loses its first create, because the plugin (and so the encoder) loads on the first Metal
device.

## Known limits

- Constant quality (QP 23): `AverageBitRate` is ignored, so bitrate varies with content and size.
- A second encoder session opened while the first is still open is refused (confirmed on the 2060 Super: -12908) ("engine already in use in this
  process", upstream issue #206). `tools/test_nvenc_h264.py` reports this check (`--overlap-required` makes it fail).
- HEVC encode stays off (a separate bitstream problem upstream).
- The encoder is CPU-bound: CPU time per frame equals wall time per frame (3.6 ms at 1080p), so one core is the limit.
  Hypothesis, not measured: the CPU writes the tiled frame through the 256 MB BAR1 mapping into video memory.
- Rows must be a multiple of 16 bytes wide in the replacement loops.
- Only the 2.2.0 encoder is supported; `make_nvenc_t2d.py` refuses other builds.

## Running the regression test

On the Mac with the driver installed:

```bash
python3 tools/test_nvenc_h264.py --log ~/nvenc-test.log
```

It builds `tools/nvenc_psnr.m`, encodes at four sizes (1366x768 is not a multiple of 16 wide), decodes with Apple's
software decoder, and requires mean and minimum PSNR of at least 40 dB. Exit 0 passes, 1 fails, 77 means skipped (not
macOS).
