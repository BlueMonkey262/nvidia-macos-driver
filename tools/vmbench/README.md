# VM measurement tools

Small macOS programs used to measure one guest: present cadence, screen-capture rate and latency, OpenGL swap pacing, tearing, minification and anti-aliasing, encoder quality, and the bitrate of a stream on the wire. They are source in this directory. `build_all.sh` compiles them on macOS into `out/` and does not install anything. This tree was prepared on Linux, so nothing here has been compiled or run from this checkout.

Each program's header has the build line, the exit codes, and what that program cannot show. The baseline numbers near the end are from the guest described below.

The guest these were measured on is macOS 15.8.1, an RTX 2060 Super (8 GB, BAR1 window 256 MB), driver 2.3.6 with this fork's plugin, and a physical monitor. The display mode is part of every row: 60 Hz and 120 Hz do not share a result.

`stdev` in these programs is the population standard deviation of the intervals (the sum of squared deviations divided by the number of intervals). Percentiles are ranks in the sorted intervals (`n/20` for p5, and the matching rank from the top for p95 and p99).

## Which tools matter

| Tier | Programs | Use them to |
|---|---|---|
| Start here (anyone streaming or checking smoothness) | `dpres`, `dcap` / `dsck`, `dlat`, `cadence`, `dnoise`, `streamrate.sh`, `tearscan` | see whether frames are presented evenly, how fast and how late a capture API delivers them, whether the picture tears, and what bitrate a stream really uses |
| Encoder checks | `encq`, `qualprobe`, `dnoise`, `streamrate.sh` (and `tools/nvenc_psnr.m`, `tools/bench_nvenc.m` one level up) | compare hardware and software encodes, see what the Quality property does, check bitrate control |
| OpenGL and display | `dgl`, `dbar`, `blendbench`, `dlink`, `tearpng` | OpenGL swap pacing, a Metal bar for tearing, GPU fill rate, display-link timing |
| Compositor image-quality investigation | `aaedge`, `minify`, `cilanczos`, `fcon`, `skylib`, `skymip`, `dscale`, `cpuicon`, `dshot` | reproduce the Dock-icon and downscale-aliasing findings; useful to someone working on the shader or compositor path |

All of them are single source files with the build line in `build_all.sh`, so they are easy to copy and change. Nothing is distributed as a binary.

## Build and launch

On the guest, from this directory:

```bash
./build_all.sh
```

That writes `out/<name>` and `out/<name>.app`. The app bundle is ad-hoc signed (`codesign -s -`) and its `Info.plist` is generated by `wrap_app` in the script. Capture programs need the bundle: Screen Recording is granted to a bundle id (`local.vmbench.dcap` and the others), and a binary started by ssh is a different process, so TCC gives it no frames. Launch with `open` so the window lands in the GUI session:

```bash
open -a "$PWD/out/dcap.app" --args 120 6 --stdout /tmp/dcap.out --stderr /tmp/dcap.err
```

The first launch of `dcap`, `dlat`, `dlat2`, `dsck`, or `dshot` needs Screen Recording enabled for that bundle, then the app has to be opened again. Programs that only draw or encode (`dgl`, `dpres`, `dnoise`, `dscale`, `aaedge`, `encq`, `cadence`, …) have no TCC prompt; the `.app` is still how `open -a` finds them. `cadence`, `aaedge`, `minify`, `cilanczos`, `fcon`, `skylib`, `skymip`, `encq`, `qualprobe`, `dlink`, and `cpuicon` can also be run as `out/<name>` from a shell on the guest.

## Present cadence

`cadence` polls a sysctl, by default `debug.nvaccel_iop_ok`, which counts presents. It prints bursts per second and the gap between bursts. Gaps over 33 ms miss a 30 Hz slot; gaps under 8 ms are two presents inside one 60 Hz refresh. Increments that land between two polls are counted as "hidden inside a poll step" and have no gap of their own. The first line is the median poll step. The poll spins one core for the whole run, so the machine is under that load while the numbers are taken. The figures in the table were taken with an older build that called `nanosleep` for 0.5 ms; that sleep wakes on the scheduler tick, so those stdevs include poll quantisation. A new run is comparable in shape (a flat refresh period, or a pile of short gaps) and prints its own poll step.

`dpres` submits one Metal drawable per `CVDisplayLink` tick and records `presentedTime`. Submitted and presented can differ: a drawable with no handler call was not presented. On a steady panel the median gap should be the refresh period (16.7 ms at 60 Hz, 8.3 ms at 120 Hz) and the stdev should be a fraction of a millisecond.

`dlink` times the display-link callback alone, with no window and no present. The mode's refresh rate can print as 0.00 Hz; the "nominal period" line is the link's own period. A tight `dlink` and a loose `dgl` means the timer is fine and the OpenGL wait is not.

## Capture rate and latency

`dcap` (AVFoundation `AVCaptureScreenInput`) and `dsck` (ScreenCaptureKit `SCStream`) draw a moving box and time the capture callback. The requested fps is a cap (`minFrameDuration` / `minimumFrameInterval`), not a promise. `dsck` drops frames whose status is not complete, and its `queueDepth` is 5. Rate and latency are separate: on this guest an SCK animation at a 120 fps request came back near 60 fps, while the same API's present-to-callback time was 1–2 ms.

`dlat` is AVFoundation only. `dlat2` is the same test with a fourth argument: the literal `sck` selects ScreenCaptureKit, and the fifth argument is `queueDepth` (default 5). Both flip a Metal window between red and blue about every 250 ms and time the gap from `presentedTime` to the callback that first shows that colour. The median is the number to compare. One pixel at the window centre is the whole signal, read as BGRA and scaled from display points into the buffer (the same pixel when the buffer is 1×). A run that prints "too few matches" had no live callback, which is the Screen Recording refusal, or the sample missed the window.

## OpenGL swap pacing

`dgl` is a double-buffered `NSOpenGLView`. `layers` is how many full-window translucent quads are drawn per frame. The printed intervals are `flushBuffer` to `flushBuffer`, with swap interval 1 unless you pass another. The histogram bins those intervals against 16.7 ms. A panel that is pacing the swap should be almost all `1x` and the fps should be the refresh rate. On this guest the median sat on 16 ms while the mean was 14–15 ms, because about 11% of swaps returned in under 8 ms: extra flushes that did not wait for the next refresh. Raising `layers` from 0 to 300 did not change that. Swap interval 0 ran at 287 fps, so the cap that does exist is the swap wait, and it is loose. `dpres` on the same 60 Hz copy path was 59.2/s with stdev 0.56 ms, so the loose result is the OpenGL path (flush through AppKit), not presents in general.

## Tearing

`dgl` also draws a full-height white bar that steps about 7 px per frame across its 960-wide window. Watch it on the physical monitor. A horizontal seam (the top of the bar at one x, the bottom at another) is a tear. The printed fps does not say whether the seam was there. The copy path is `debug.nvaccel_iop_flip=0` (the kernel copies each frame, no vsync). `debug.nvaccel_iop_flip=1` is the zero-copy flip. The recorded visual result, on a quiet 1080p60 desktop, used a Metal window whose bar stepped 37 px/frame: the copy path tore on every frame, and the flip path was mostly clean with rare tiny tears. That 37 px program is not in this directory; `dgl`'s bar is the check that is. `flipwatch` appends the flip counters to `/tmp/flipwatch.log` every 10 s for 40 minutes (hit, miss, stale, novram, refused, late, async drop, latch timeouts). A counter that stays 0 means that path did not run. The log cannot see a seam, and a clean counter during a game does not mean the picture looked even: the game's own frame was already torn or uneven before the present.

## Tearing inside captured content

`dbar` is a Metal window with a full-height white bar that jumps a fixed number of pixels per presented frame. `tearscan`
draws the same bar with OpenGL or Metal while ScreenCaptureKit captures the display, and counts captured frames in which
the bar sits at two x positions (a tear inside the composited content; the panel's own scan-out is not captured, so a tear
only a monitor shows is not counted). `tearscan gl 15 37 0 cap full` is a full-screen OpenGL window at swap interval 0.
Compare `gl` and `metal` in the same session. A run of a few torn frames at the start or end is a start-up artefact. Where
capture is not possible, `tearscan ... nocap` draws only, and `tearpng` analyses PNGs from `dshot`.

Measured on the guest (RTX 2060 Super, 1080p60, `tearscan`): a 1200x800 window tore in about 0.5% of captured frames for both
OpenGL and Metal; full screen at swap interval 0, OpenGL 1.7-2.0% against Metal 0.4%.

**Screen Recording and rebuilding.** macOS ties the grant to the signature of the binary, so every rebuilt capture program
needs the grant again. `capture-host` avoids that: it is a small fixed program that loads `probe.dylib` (built from
`tearscan.m` with `-Dmain=probe_main`) and runs it. Grant `out/capture-host.app` once, then rebuild `probe.dylib` freely:

```bash
open -W -a "$PWD/out/capture-host.app" --stdout /tmp/ts.out --args gl 10 37 1 cap full; cat /tmp/ts.out
```

## Minification, anti-aliasing, MPS, Core Image

These are offscreen, in this process. A pass does not mean the Dock or WindowServer took the same path.

| Program | What a pass means |
|---|---|
| `aaedge` | A squircle's edge has partial alpha from shader coverage, from 4× MSAA plus resolve, and from an A8 target. The 1-sample geometry edge must stay jagged (zero partial pixels). |
| `minify` | Shrinking a 1024 px squircle to 128 px with mip sampling stays within 3.0 mean absolute error of a CPU box filter. Nearest and non-mip rows are printed and not failed. `minify 0` or `minify 1` runs only one MPS scaler. |
| `cilanczos` | `CILanczosScaleTransform` on the Metal context, at 128, 112, 100, and 64 px, stays within 3.0 of an area-average. The software renderer is printed beside it and is not gated. |
| `fcon` | Function-constant specialisations change the clear colour of a tiny shader. "none set" must be black. |
| `skylib` | Loads the system SkyLight metallib and prints function names. It does not print bitcode. |
| `skymip` | Builds compute pipelines for the five `mipGenPolyphase*` kernels in that metallib. |
| `dscale` | Three 112×112 layers of one 1024 px squircle, for the eye: default minification, trilinear, and a CPU pre-scale. The banner gives screen coordinates (bottom-left) for a later crop. |
| `cpuicon` | Draws an app icon on the CPU at 112, 128, and 64. A smooth PNG here leaves the Dock's GPU minify as the remaining path. |
| `dshot` | One full-display PNG per argument, via ScreenCaptureKit, one second apart. |

On this guest, shader coverage, 4× MSAA, and A8 were smooth, and `generateMipmaps` plus trilinear sampling matched the box filter (mean abs error 0.01). `MPSImageBilinearScale` ran and was aliased (error 0.95). `MPSImageLanczosScale` aborted inside MPS while creating `lanczosHorizontalScale`; the process dies before `PASS`/`FAIL`, and that abort is the result.

## Encoder quality and the Quality property

`encq shot.png outprefix` encodes 30 frames (or the count you pass) with the hardware H.264 encoder and with Apple's software encoder, static and then scrolled 3 px/frame (`order` defaults to `hsHS`). It decodes with the software decoder and prints PSNR-Y for the whole frame and for the bottom 100 rows, plus the IDR size and the average frame size as Mbit/s at 60 fps. AverageBitRate is set to 25 Mbit/s; the unpatched library does not follow it and sits at a constant QP. PSNR near 50 dB on a still desktop is far above a visible loss. The session is released at the end of each run so the next letter in `order` can open the hardware engine. An earlier build only called `Invalidate`, and a second hardware session in that process failed with -12908. One engine per process is still the card: two live sessions at once are refused.

`qualprobe shot.png` keeps one hardware session and sets `Quality` before each of seven phases of 20 scrolling frames (0.50, 0.90, 0.25, 0.70, 0.50, 1.00, 0.10). After the first phase that is a mid-stream change. The library stores `qp = trunc(51 - 41*q + 0.5)`. The printed average skips the first frames of the phase so the IDR does not dominate. A Quality change the library honours moves the byte count with that QP. This probe writes Quality itself. It does not enable the plugin's rate controller.

`dnoise` is the busy picture for a live encode: a full-screen window of hashed noise at the screensaver level, default amplitude 40, for the number of seconds you pass (streamrate asks for 70). It covers the desktop. The right side of the frame uses the full amplitude.

The rate-control knob is not an environment variable on a release plugin build. Those builds strip `NVMTL_*` at load. Put `NVMTL_VT_RC=1` in `/Library/GPUBundles/nvmtl/nvrm610.conf`. `tools/vt_rc_probe.m` is the separate target-bitrate probe (8.0 Mbit/s requested, 7.99 measured).

## Bitrate on the wire

`streamrate.sh` runs on the Linux client, not on the Mac. The guest has no `timeout`. The script starts `dnoise.app` over ssh, connects Moonlight at 1080p60 H.264 for the bitrate you pass (default 25000 kbit/s), and runs `tcpdump` on the guest for 20 seconds. GNU `timeout` on the client stops Moonlight; the capture itself ends because `tcpdump -G 20` exits. Payloads under 600 bytes are left out. The first and last second are partial and are dropped. What remains is video Mbit/s on UDP port 47998 from the guest. Set `VM_ADDRESS`. Optional: `VM_USER`, `VM_SSH_KEY`, `VM_TOOLDIR` (guest directory containing `dnoise.app`, default `~/vmbench`), `VM_IFACE` (default `en0`).

```bash
VM_ADDRESS=guest.example VM_USER=me ./streamrate.sh busy 18000
```

`tcpdump` needs passwordless `sudo` on the guest (`sudo -n`). A refused sudo produces no rows. The interface has to be the one the stream leaves on.

## Pitfalls

- **Screen Recording and ssh.** TCC binds the grant to the `.app`. Build with `build_all.sh`, enable the bundle in System Settings, and launch with `open -a`. A bare binary from ssh captures nothing, and `dlat` / `dlat2` then report too few matches.
- **`NVMTL_*` on a release plugin.** The environment is stripped at load. The conf file above is what the plugin reads.
- **macOS has no `timeout`.** Do not prefix a guest command with it. `streamrate.sh` uses GNU `timeout` on the Linux client and `tcpdump -G` on the guest.
- **`echo "$(cmd) $?"` does not print `cmd`'s status.** Bash expands `$?` before the command substitution runs, so the number is the previous command. Save the output, then print `$?`:

  ```bash
  out=$(cmd)
  echo "$out $?"
  ```

- **Other load moves the numbers.** `cadence` occupies a core. `dnoise` covers the display. A stream, Minecraft, or `PerfPowerServices` (see [docs/VM-NOTES.md](../../docs/VM-NOTES.md)) on the same guest changes present gaps and capture fps. Measure one thing at a time, and write down what else was running.
- **`tcpdump` needs sudo.** Without it the pcap is empty and there is no mean to interpret. The filter is the guest's source address and UDP 47998; another flow from that host on that port is included.

## What a run still cannot prove

A good `dpres` and a bad `dgl` localise the loose pacing to the OpenGL flush, and they do not say which lock inside that flush. A 1–2 ms SCK callback is not glass-to-glass: encode, the network, and the client are still ahead of it. A clean flip counter during a game does not mean the monitor looked steady. A passing `aaedge` or `minify` does not mean WindowServer's resample shader ran. PSNR on one screenshot does not describe a motion-heavy stream; the wire number from `streamrate` is the size on the network, including FEC, and it is not a picture-quality figure.
